Fix OpenRouter 405 error with comprehensive debug logging

## Problem
Users were experiencing 405 Method Not Allowed errors from OpenRouter API
with empty response bodies, making it difficult to diagnose the root cause.

## Solution
Added comprehensive debug logging throughout the extension to help identify
and fix 405 errors by showing exactly what's being sent to and received
from OpenRouter.

## Changes Made

### Modified: avo/popup.js
1. Enhanced loadSettings() function:
   - Added detailed logs showing loaded model name
   - Validates API key format (checks for sk-or-v1- prefix)
   - Shows if API key is present or missing
   - Displays default model being used

2. Enhanced saveSettings() function:
   - Logs model being saved
   - Shows API key prefix being saved
   - Confirms successful save with log
   - Logs errors if save fails

3. Completely rewrote callOpenRouter() function:
   - Request preparation logs:
     * Selected model name
     * API endpoint URL
     * API key prefix (first 30 chars)
     * Full request body in formatted JSON
   
   - Response logs:
     * HTTP status code and text
     * Response headers (content-type, rate limits)
     * Raw response body before parsing
   
   - Enhanced error handling:
     * Attempts to parse error JSON from response
     * Handles empty response bodies specifically
     * Provides clear error message for 405 with empty response
     * Validates response structure
   
   - All logs use emoji prefixes for easy filtering:
     * 🔄 [DEBUG] - Request preparation
     * 📊 [DEBUG] - Response received
     * ✅ [DEBUG] - Success/loaded
     * ❌ [ERROR] - Error occurred
     * 💥 [ERROR] - Critical error
     * 💾 [DEBUG] - Saving data
